# 02 — 用户与场景

## 主用户（MVP）

**中文独立开发者 / 学习者**

- 能克隆仓库、配置环境变量、本地启动；
- 关心「内容模型、工作流、导出质量」等设计，而不只是按钮；
- 可能 fork、提 Issue，或把羽师当作品集参考。

## 次用户（远期）

**非技术知识工作者**（教师、运营、咨询等）

- 要「粘贴材料就出片」；
- 需要托管、易用账号与更强的模板；
- **不进入 MVP**；能力清单中的交互以「可演进到他们」为准，但不为实现他们而提前做账号与计费。

## 作者角色

作者本人是第一名 dogfood 用户，也是内容分发者：

- 用羽师产出演示稿与录课辅助材料；
- 用同一作品向 B 站、公众号、GitHub Star 导流。

## 核心场景

### S1 — 主题出片（幸福路径主路径）

1. 本地启动羽师；
2. 输入一个输入主题（短文本）；
3. 生成大纲，修改后确认；
4. 并发生成不少于 5 页；
5. 在编辑器修改一处文案，确认写回内容模型；
6. 通过质量门禁；
7. 下载 PPTX，在 PowerPoint 或 WPS 中能直接改文字（非整页图片）。

### S2 — 文档出片

1. 上传或粘贴 Markdown / TXT / PDF / Word 之一；
2. 系统抽取或归纳后生成大纲，用户确认；
3. 后续与 S1 相同。

### S3 — 单页失败可恢复

1. 多页生成中某一页失败；
2. 用户仅重试该页，不必推翻整份稿件；
3. 进度可见。

### S4 — 人工编辑优先于再生成

1. 用户改过的块标记为锁定；
2. 再次触发 AI 相关操作时不覆盖锁定内容。

### S5 — 作品讲解（内容侧）

1. 作者按课程原料录制 B 站或写公众号；
2. 演示 S1 录屏；
3. 讲解内容模型、门禁与原生导出等抉择（不依赖未公开私参课件）。

## 非场景（MVP 不承诺）

- 多人同时编辑同一稿件；
- 浏览器免安装的公网服务 SLA；
- 「一句话生成精品设计稿」的纯审美竞赛（羽师优先可控与可导出）。
