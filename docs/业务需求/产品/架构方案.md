## 运行单元

浏览器里是一个中文 React 单页应用。它保存编辑中的界面状态，通过 HTTP 读写稿件，通过 SSE 接收每一页的生成进度。

服务端是两个 Python 进程，共用同一套领域代码：

- API 进程提供 HTTP 和 SSE，使用 FastAPI。
- 生成进程使用 ARQ，从 Redis 取出页面任务。

PostgreSQL 是使用者和稿件的权威记录，包括大纲、页面、内容模型、主题选择、预设布局选择、锁定和页面是否完成。Redis 只做两件事：ARQ 的任务队列，以及把进度转给 API。ARQ 不保存稿件内容。对象存储保存文件字节。

```text
浏览器
  |  HTTP / SSE
API 进程 ---- PostgreSQL（稿件与完成状态）
  |                ^
  | Redis 进度      | 写入内容模型与状态
  v                |
生成进程 -- Redis 队列（ARQ）
  |
  +--> 可配置的对话接口
  +--> 对象存储（文档、图片、PPTX）
```

Redis 里的进度消息可以丢失。API 以 PostgreSQL 中的页面状态为准，把未完成的页重新入队。

## 稿件数据

内容模型是渲染之前的结构。Web 预览和 PPTX 导出都读它，不把自由 HTML 或成品 PPTX 当成稿件本身。

一页的内容块只有标题、正文、要点、图片、表格、图表。图表只记录柱状或折线，以及带出处的数字。图片块记录占位，或一个文件引用。

预设布局是产品自带的七种命名排布：封面、章节、要点、双栏、图文、表格、图表。主题是产品自带的视觉皮肤，至少一浅一深。二者都与文案分开存放。换布局不改要点，换主题不改文案。

页数始终在 5 到 20 之间。大纲确认前，输入材料可以增减。确认后，输入材料不再变化；页面仍可在这个页数范围内增删。新增页进入生成队列。

## 生成

生成进程按页调用可配置的对话接口，要求结构化输出，再做业务校验，然后写入该页的内容模型。校验失败或调用失败只标记该页，并用 ARQ 支持单页重试。使用者可以取消尚未开始的页。

同一稿件同时进行的页面任务不超过 3 个。演示站另有全站并发上限，写在配置里。自行部署可以提高自己的全站上限，不能提高单稿 3 页这一条。

模型供应商不写进领域代码的分支里。换供应商是改配置。

## 编辑

直接编辑和改页都提交到内容模型。使用者亲手改过的内容块写入锁定。之后的改页和单页重新生成跳过锁定块。解除锁定是一次显式操作。

界面上的保存以页面为粒度排队。后一次保存要能发现自己基于过期修订，不能悄悄盖掉中间的修改。

## 导出

导出只读 PostgreSQL 中的内容模型和对象存储中的图片引用。质量门禁分成错误和警告，规则见产品需求。错误阻断导出。

通过门禁后，生成进程或 API 中的导出步骤用产品自带的思源黑体嵌入 PPTX，正文写成可编辑的文本框、表格和图形。成品 PPTX 作为文件写入对象存储，稿件保存引用。

## 文件与下载

所有正式文件都通过 S3 兼容协议存放。演示站和自行部署只是端点、密钥和桶名不同。本地开发使用同一个协议的端点，例如 MinIO，不另做「磁盘即正式库」。

桶不允许公开读取。下载请求先确认当前账号拥有该稿件，再签发短时读取地址。有效时长放在配置里，默认十分钟。

## 账号

登录身份是邮箱加密码。演示站关闭公开注册，不提供注册接口；部署者用管理命令开设账号。自行部署用一个开关打开公开注册。第一版没有验证邮件、找回密码、邀请码和微信登录。

密码只保存散列。登录后的访问凭证由 API 签发，使浏览器可以调用后续接口。

## 部署形态

第一版的目标是一份可自行部署的多账号应用，外加羽师自己的演示站。演示站用于发行，不是收费托管。

一套运行至少包含：API 进程、生成进程、PostgreSQL、Redis、一个 S3 兼容桶。公开仓库的许可证为 AGPL-3.0。
