# 01 — 羽师作品全景

## 一句话主张

AI PPT 的胜负手不是「文案更华丽」，而是**可确认、可编辑、可校验、可原生导出的闭环**。

## 问题场景

你让模型「直接做一页 PPT」。它给你一段 HTML 或一堆无法改的图片。第二天客户要改副标题第三个字——你只能整页重生成，版式全乱。  
观众要的是：**改得动、导得出、讲得清架构**。

## 错误做法

- 模型直接生成最终 HTML/PPTX，前端只负责展示；
- 用整页截图冒充「已经导出」；
- 没有大纲确认，十页写完才发现叙事跑偏；
- 把「换更贵的模型」当成唯一架构。

## 设计抉择

1. **先大纲、后页面**：人工确认叙事；  
2. **内容模型为唯一真相**：预览、编辑、门禁、导出同源；  
3. **内容 / 布局 / 主题分离**；  
4. **门禁之后才导出**；  
5. **导出必须原生可编辑**。  

羽师 MVP 还约定：本地单用户；输入含主题与 MD/TXT/PDF/Word；配图先占位；MIT 开源服务个人作品引流。

## 羽师中的对应模块

- 产品文档：`docs/业务需求/产品/01`～`04`
- 能力：整条幸福路径（P0 全表）
- 术语：稿件、大纲、内容模型、质量门禁、原生可编辑导出

## 演示脚本

1. 亮出「坏结果」对比：截图型 PPT vs 可改文字的 PPTX（可用示意）；  
2. 画出闭环：输入 → 大纲确认 → 生成 → 编辑 → 门禁 → 导出；  
3. 打开羽师，只跑到「生成大纲并改一句」停住，预告后续集展开；  
4. 一句话收束：作品要能录屏验收，而不是只存在于幻灯片构想。

**口播时长建议：** 8–12 分钟。

## 练习 / 作业

用三句话写清你心中的 AI PPT「不可妥协」清单，并标出哪一条若拿掉会导致无法原生导出或无法局部修改。
