# 05 — 分层校验与可用优先

## 一句话主张

用「格式 → 结构 → 业务」分层挡住坏输出；失败时降级到仍能走完闭环，而不是追求一次完美。

## 问题场景

模型偶尔少一个 `key_points`，偶尔把图写成空 URL。若你只会「整段重试」，成本高且用户只看见转圈。

## 错误做法

- 信任自由文本，用一堆正则碰运气；  
- 任何子步骤失败就让整份稿件作废；  
- 没有业务规则（例如至少 1 个要点）就放行。

## 设计抉择

1. **格式层**：约束 JSON / 工具输出形态；  
2. **结构层**：schema（字段、类型、必填）；  
3. **业务层**：页数、敏感空洞、门禁规则等；  
4. **降级**：配图 MVP 直接占位；解析失败给出可操作错误，不装死。  

「能用优先于完美」——占位图可以丑，但不能挡住导出可编辑文本。

## 演示脚本

1. 演示一次「缺字段」被结构层拒绝；  
2. 演示修复或重试后通过；  
3. 演示无图时落入占位，幸福路径仍能导出；  
4. 收束：分层防御是工程，不是提示词玄学。

**口播时长建议：** 12–16 分钟。
