# 06 — 带错修复的生成回路

## 一句话主张

生成流水线应是「生成 → 检查 → 带着问题修复」，并给修复轮次上限；盲重试不是工作流。

## 问题场景

同一页第三次重试仍缺表头。用户不知道系统在干什么，你也不知道是提示词问题还是 schema 太严。

## 错误做法

- 失败就整页从头再请模型写一遍，不告知上次错在哪；  
- 无限修复，账单与时延失控；  
- 把「工作流」写成深不可测的单文件脚本，无法单步看状态。

## 设计抉择

- 显式状态：生成、校验、修复、成功/失败；  
- 修复输入包含**结构化错误描述**；  
- **轮次上限**后暴露给用户「单页重试」；  
- 与页级异步任务结合（下一集）：一页卡死不应拖死全稿。

实现可用图状态机或等价编排；需求只要求行为可观察、可限次、可归因。

## 羽师中的对应模块

- P0-08 结构化输出与有限次修复  
- P0-06 / P0-07 页级任务与重试

## 演示脚本

1. 画状态图：generate → check → repair → done；  
2. 日志或 UI 展示「第 2 次修复：缺少 bullets」；  
3. 触达上限后的用户提示；  
4. 对比盲重试：同样三次，自纠更可讲、可调。

**口播时长建议：** 12–15 分钟。

## 练习 / 作业

设计 3 条「可回灌给模型的错误信息」模板（要具体到字段，不要只说「格式错误」）。

## 下期钩子

页数一多，同步请求会把浏览器和接口一起拖死——下一集把长任务拆成页级异步。
