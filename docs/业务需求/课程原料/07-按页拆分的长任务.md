# 07 — 按页拆分的长任务

## 一句话主张

长任务按页拆开：进度可见、失败可单页重试、取消不毁掉已成功的页面。

## 问题场景

10 页同步生成，用户盯着转圈 3 分钟，第 8 页失败后全部作废——这是劝退设计。

## 错误做法

- 一个 HTTP 请求从头堵到尾；  
- 取消等于进程杀掉且清空成功页；  
- 没有页级状态，只能显示「处理中…」。

## 设计抉择

- **页级任务**入队或等价并发；  
- UI 订阅进度（轮询或推送均可，需求不锁协议）；  
- **软取消**：未开始的不再跑，已成功的保留；  
- 与大纲确认衔接：未确认不得投递页任务。

## 羽师中的对应模块

- P0-06 页级生成  
- P0-07 进度与软取消  
- 场景 S3

## 演示脚本

1. 启动 ≥5 页生成，UI 逐页变「完成」；  
2. 人为让一页失败（或模拟），点「重试该页」；  
3. 生成中途点取消，展示已完成页仍在；  
4. 收束：异步是体验与成本控制，不是炫技。

**口播时长建议：** 10–14 分钟。
