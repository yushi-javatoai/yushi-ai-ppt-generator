# 08 — 改稿写回与锁定

## 一句话主张

编辑器是内容模型的手术台：改动必须写回；锁定块禁止被后续 AI 覆盖。

## 问题场景

用户改好了副标题，又点了「优化本页」，AI 把人工字全盖掉——信任归零。

## 错误做法

- 编辑只改 DOM，刷新即丢；  
- 再生成无视人工编辑；  
- 用「整页 HTML 替换」当保存。

## 设计抉择

- 所有编辑 → 模型补丁；  
- **锁定（locked）**语义明确；  
- 用修订号等方式提示冲突（实现可选，行为要有）；  
- 不支持把编辑器退化成自由文档处理器却仍声称能原生导出。

## 羽师中的对应模块

- P0-10 在线编辑写回与锁定  
- 场景 S4  
- 术语：锁定（locked）

## 演示脚本

1. 改一处正文，刷新仍在；  
2. 锁定该块，触发再生成/优化，锁定块保持；  
3. 未锁定块允许更新；  
4. 收束：人工优先是产品伦理，也是导出一致性的前提。

**口播时长建议：** 10–13 分钟。
