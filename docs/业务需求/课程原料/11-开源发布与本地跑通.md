# 11 — 开源发布与本地跑通

## 一句话主张

先让本地幸福路径可录屏、MIT 仓库可浏览，再谈公网托管；公开仓保持干净，不夹带未授权私参材料。

## 问题场景

作者卡在「还没上云就不算作品」，迟迟不公开，也就没有 Star 与片。另一极端：仓里塞满密钥、课件爬取件，审稿与信任双杀。

## 错误做法

- 无 LICENSE、无 README 幸福路径；  
- 把 `.env`、私钥、未授权课件推进 GitHub；  
- MVP 未完成就承诺 SaaS SLA；  
- 为了「看起来有运维」上复杂 K8s，却跑不通 5 页导出。

## 设计抉择

- **MIT** 许可；  
- README：快速开始 + 幸福路径验收清单；  
- MVP：**本地单用户**即可宣告阶段完成；公网 Demo 是加分项；  
- 私参目录保持未跟踪；对外叙事只讲羽师；  
- 非目标清单写进产品需求，避免评论区催账号体系。

## 羽师中的对应模块

- 产品 `01` 愿景与公开叙事  
- `04` 许可、DoD、非目标 N-01～N-07  
- 个人作品导流：GitHub → B 站 / 公众号

## 演示脚本

1. 展示仓库根：LICENSE（MIT）、README 验收清单；  
2. 本地跑通导出（可剪辑第 04 集画面）；  
3. 展示「非目标」列表，降低错误预期；  
4. 预告连载如何用 01–10 原料切片更新——作品是长期资产，不是一集爆款。

**口播时长建议：** 8–12 分钟。

## 练习 / 作业

写一版 15 行以内的 README「快速开始」草稿（命令可用占位符），并附 7 步幸福路径勾选列表。
