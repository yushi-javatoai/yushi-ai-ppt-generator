# 13 — 作品经历怎么写进简历

## 一句话主张

简历只写可验证结果：闭环、约束、你做的设计抉择，而不是堆技术名词。

## 问题场景

「参与 AI PPT，用了某某框架」——面试官无法追问，也无法核对 GitHub。星标与 B 站播放若对不上简历句子，可信度反而下降。

## 错误做法

- 把整份依赖列表当业绩；  
- 夸大「从 0 发明 PPT 格式」；  
- 不写验收标准（能否原生改字、能否单页重试）；  
- 暗示复制某商业课仓库作为个人成果。

## 设计抉择

推荐条目结构（每条一行结果 + 一行约束）：

1. **结果**：本地可运行的 AI PPT，大纲确认后页级生成，导出可编辑 PPTX；  
2. **约束**：内容模型单一数据源；error 级门禁阻断导出；MIT 开源；  
3. **你的贡献**：点名你负责的模块（模型 / 导出 / 编排 / 门禁等）；  
4. **证据链接**：仓库、一分钟录屏、对应课程篇。

## 羽师中的对应模块

- 个人作品定位（`GLOSSARY` / 产品 `01`）  
- DoD 幸福路径  
- 对外叙事原则（不绑第三方教程品牌）

## 演示脚本

1. 展示「坏简历句」vs「好简历句」对照；  
2. 打开 GitHub README 的验收清单，说明可核对；  
3. 用 30 秒口述：输入 → 门禁 → 可改字导出；  
4. 提醒：播放量是加分，闭环才是主句。

**口播时长建议：** 8–12 分钟。

## 练习 / 作业

写 3 条简历 bullet（各不超过 40 字），并标注每条对应的仓库证据位置。

## 下期钩子
