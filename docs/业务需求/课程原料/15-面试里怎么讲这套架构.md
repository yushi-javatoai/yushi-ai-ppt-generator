# 15 — 面试里怎么讲这套架构

## 一句话主张

用「场景 → 约束 → 抉择 → 后果」讲羽师，比背组件名更能证明你是设计者。

## 问题场景

面试官问「项目亮点」。你从框架一路背到队列，五分钟后对方仍不知道用户怎么改第三页副标题。

## 错误做法

- 先甩技术栈再找问题；  
- 回避「导出可编辑」这类可证伪点；  
- 贬低他人方案衬托自己；  
- 把私参课讲义当答案朗读。

## 设计抉择

推荐 90 秒结构：

1. **场景**：改一个字不能整页重生成；  
2. **约束**：预览与导出同源；本地可跑；MIT；  
3. **抉择**：内容模型 + 大纲确认 + 页级任务 + 门禁 + 可改字导出；  
4. **后果**：单页可重试、锁定防覆盖、截图方案直接不合格。

深挖题库（自备）：模型乱输出怎么办、为何按页异步、门禁分级、布局为何不让模型写死坐标。

## 羽师中的对应模块

- 全线 P0 与术语表  
- 课程 02 / 04 / 07 / 08 / 10 为高频深挖点

## 演示脚本

1. 你按 90 秒结构口述一遍（可录）；  
2. 模拟追问「为何不做同步大请求」；  
3. 模拟追问「警告和错误差在哪」；  
4. 收束：作品链接 + 录屏是物证。

**口播时长建议：** 10–14 分钟。

## 练习 / 作业

对着手机录两条：90 秒总述 + 一条深挖（自选门禁或导出）。回听删掉所有无法指向仓库行为的空话。
