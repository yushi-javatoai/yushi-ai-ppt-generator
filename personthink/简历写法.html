后端写法

冒号前的内容只是为了帮助大家快速理解每一点的核心内容，写在简历上时可以移除掉。

  1. 【推荐】内容模型设计：设计了内容、布局、主题三分离的数据模型，定义 6 种内容块类型（标题、要点、KPI、图片、表格、图表），通过 960×540pt 归一化坐标系统一前后端渲染和 PPTX 导出的定位基准。（第 2 期）

  2. 【推荐】PPTX 导出引擎：基于 python-pptx 逐块构造 PowerPoint 原生对象（文本框、表格、图表），解决了东亚字体 a:ea 标签、emoji 处理、文本框自适应 spAutoFit 等 OOXML 难点，实现导出后文字/表格/图表均可直接编辑。（第 4 期）

  3. PPTX 回读验证：实现导出后自动回读验证机制，检查文字是否在文本框中、表格是否原生表格、是否存在整页位图等 7 项可编辑性指标，保证导出质量。（第 4 期）

  4. 【推荐】AI 结构化输出：通过 LangChain LCEL 链 + with_structured_output(json_mode) 保证模型输出为强类型 Pydantic 对象，结合业务规则校验（layout_id 合法性、块类型匹配、数值范围）构建五层防御漏斗，保证 AI 输出始终可用。（第 5 期）

  5. 图片降级链：设计 AI 生图 → 图库搜索 → 占位图的三级降级策略，每级失败自动降到下一级，API 超时或额度耗尽不影响核心生成流程。（第 5 期）

  6. 【推荐】AI 生成工作流：基于 LangGraph StateGraph 实现大纲生成（线性）和单页生成（自纠环路）两种工作流，单页工作流包含 prepare → generate → check → repair 四节点，通过条件边根据校验结果决定是否触发修复轮次。（第 6 期）

  7. 上下文裁剪：对用户输入的来源文本按 token 预算进行裁剪，避免超出模型上下文窗口；裁剪后保留前后文各占一半，保证信息覆盖的均匀性。（第 6 期）

  8. 【推荐】异步任务编排：基于 ARQ（异步 Redis 队列）实现生成任务的异步派发，采用 “先落库后入队” 模式保证任务不丢失，通过 asyncio.Semaphore 控制页级并发度（默认 3 页并行）以适配 LLM 供应商限流。（第 7 期）

  9. 【推荐】实时进度推送：基于 Redis pub/sub 实现生成进度的实时推送，通过 SSE（Server-Sent Events）将进度事件流式传给前端；同时每条事件写入 Redis 快照，支持 SSE 断线重连时补发丢失的事件。（第 7 期）

  10. 幂等断点续跑：通过 sync_slides 比对已有页面跳过已完成的页面，实现生成任务的断点续跑；结合 job_id + revision 乐观锁防止迟到结果覆盖新数据。（第 7 期）

  11. 软取消机制：通过 Redis 标记位实现生成任务的软取消，Worker 在每页生成前检查标记位，已完成的页面保留、未开始的页面跳过，避免硬杀进程导致数据不一致。（第 7 期）

  12. 【推荐】布局求解器：实现基于 FlexContainer/FlexLeaf 树结构的布局求解算法，通过 ratios（水平分配比）、grow（垂直权重）、gap（间距）、bleed（出血）四个参数递归分割画布区域，支持 AI 生成任意版式。（第 9 期）

  13. 布局归一化：实现 normalize 函数对布局树做美观修正（比例吸附、权重钳制、深度限制），保证幂等性。（第 9 期）

  14. 【推荐】文字溢出检测：基于 FontTools 读取字体文件的 cmap + hmtx 表计算每个字符的 advance width，实现拉丁整词断行、CJK 逐字断行的折行算法，在保存和导出时检测文字是否溢出文本框。（第 10 期）

  15. 度量降级：设计三层降级策略（fontTools 未安装 → 字体文件不存在 → 字符无字形），任何层级的缺失都不抛异常而是走估算路径，度量结果标注是否为估算值。（第 10 期）

  16. 【推荐】分级质量门禁：设计 warning/error 分级的质量检查体系，error（内容超出画布、图片缺失）阻断导出，warning（溢出槽位、内容重复、空话占位）仅提示；导出前串联画布尺寸、槽位越界、内容溢出、图片完整性、内容质量等检查项。（第 10 期）

  17. 回归测试：基于固定 JSON 语料（非真实模型调用）构建回归集，覆盖全部布局模板 × 全部主题的组合，验证 PPTX 可编辑性 100%、溢出率 < 5%、换主题不改内容。（第 10 期）

  18. 存储驱动抽象：通过 Storage Protocol + 工厂函数实现本地文件系统和 COS 对象存储的无缝切换，COS SDK 惰性导入避免本地开发安装无关依赖；LocalStorage 包含路径穿越防护。（第 11 期）

  19. 【推荐】安全设计：登录接口对不存在用户做假哈希验证消除时序侧信道；项目归属校验统一返回 404（而非 403）防止 ID 枚举；media 接口因 <img> 无法携带 Authorization 头而设计为不鉴权，通过 UUID key + 前缀隔离保障安全。（第 11 期）

  20. 内容感知排版：在生成阶段根据实际内容长度动态调整布局树（fit_row_widths 按文字量重分列宽、fit_tree_to_content 按块高度调 grow 权重），避免内容和容器不匹配。（第 9 期）

前端写法

  1. 【推荐】等比缩放渲染：基于 CSS 容器查询单位 cqw 实现 PPT 页面在缩略图（160px）、编辑画布（800px）、全屏演示（视口宽度）三种尺寸下的严格等比渲染，所有尺寸共用同一个 SlideView 组件。（第 3 期）

  2. 图表适配：针对 Recharts 等不支持 cqw 单位的第三方图表库，通过 ResizeObserver 监听容器实际像素尺寸，用 transform: scale() 将固定像素渲染的图表缩放到容器查询坐标系中。（第 3 期）

  3. 【推荐】结构化编辑器：基于 contentEditable="plaintext-only" 实现文本编辑，采用非受控组件模式分离 value（已保存值）和 draft（当前输入），通过 SAVE_IDLE_MS = 800 延迟提交 + blur 立即提交，避免编辑过程中频繁触发保存。（第 8 期）

  4. 光标管理：实现 caretAtChange 算法在 DOM 更新后精准恢复光标位置，使用 document.execCommand('insertText') 拦截粘贴事件实现纯文本粘贴。（第 8 期）

  5. 列表编辑语义：为要点列表实现 Enter 新增条目、空行 Backspace 删除条目、方向键跨条目跳焦的键盘交互，模拟类文档编辑体验。（第 8 期）

  6. 【推荐】两层撤销：实现本地草稿撤销（pendingRedoRef，未提交的文字变更）和页面级历史撤销（undoStackRef/redoStackRef，已提交的内容变更）的分层 undo/redo 机制。（第 8 期）

  7. 【推荐】乐观更新和冲突处理：通过 queryClient.setQueryData 实现乐观更新，编辑操作立即反映到 UI；每次保存携带 revision，后端 409 冲突时前端自动拉取最新数据合并，保证多端编辑的数据一致性。（第 8 期）

  8. 按页串行保存队列：实现 useSlideSaveQueue 保证同一页的多次保存请求按序执行，避免乱序请求导致 revision 跳变引发 409 冲突。（第 8 期）

  9. 【推荐】SSE 流式消费：基于自定义 fetch（而非原生 EventSource）实现 SSE 客户端，支持 Authorization 头、手动解析 data: / event: 行、自动重连和心跳检测。（第 7 期）

  10. 【推荐】布局树求解器：用 TypeScript 复现 Python 侧的递归面积分割算法（flexLayout.ts），通过 golden sample 测试（flex-parity.mts）保证前后端对同一棵布局树的求解结果完全一致。（第 9 期）

  11. 布局可视化编辑：实现 FlexEditLayer 组件，支持拖拽调整分栏比例、插入/删除布局节点（insert_leaf / remove_leaf_by_block_id），操作后自动清理空容器（prune_empty_containers）。（第 9 期）

  12. 类型安全：通过 openapi-typescript 从后端 OpenAPI schema 自动生成 schema.d.ts，前端使用 components['schemas'] 消费后端类型，结合 Omit 桥接少量本地类型差异，后端接口变更时前端编译立即报错。（第 10 期）

个人评价

  1. 具备全栈 AI 应用开发能力，熟练掌握 FastAPI + LangGraph 后端和 React + TypeScript 前端，能独立完成从 AI 工作流到在线编辑器的完整系统开发。

  2. 具备系统的质量工程意识，能设计从文字度量、分级告警到导出门禁的完整质量体系，将问题前移到编辑和导出环节拦截，而非留给用户发现。

  3. 注重前后端一致性，通过 OpenAPI 单源类型生成消灭接口漂移，通过 golden sample 测试保证双端求解器输出一致，通过共享常量保证度量和导出对齐。

  4. 具备安全工程意识，能从时序侧信道、ID 枚举、路径穿越等攻击面出发设计防御措施，理解 Web 平台限制（如 <img> 无法携带 Authorization 头）并设计合理的替代方案。

  5. 具备渐进降级设计能力，在字体缺失、AI 输出异常、图片获取失败等场景下设计多级降级策略，保证系统在依赖不完备时仍然可用。

  6. 自主学习和问题解决能力较强，能深入理解 OOXML 文档格式、FontTools 字体度量、CSS 容器查询等专业领域技术，并将其应用到实际产品中解决工程问题。

  7. 注重开发体验和工程实践，通过 Docker Compose 编排基础设施、统一端口规划、Makefile 自动化常用命令，降低项目上手门槛。
